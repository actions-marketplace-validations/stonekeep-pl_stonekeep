# Test fixture repos

Small, self-contained "repositories" used by the test suites. All data is fake.

| Fixture           | Sources                                       | Purpose                                                                 |
| ----------------- | --------------------------------------------- | ----------------------------------------------------------------------- |
| `prisma-app`      | `prisma/schema.prisma`                        | Emails/phones in Prisma models, `@map`, relations, enums                |
| `sql-migrations`  | `migrations/*.sql` + committed datamap        | Replay of CREATE/ALTER/RENAME/DROP; baseline for `stonekeep check` tests |
| `typeorm-openapi` | TypeORM entity, OpenAPI YAML, JSON Schema     | Decorators, nested schemas, `format`, config overrides and excludes     |

If you change `fixtures/sql-migrations`, regenerate its datamap:

```bash
pnpm build && node packages/cli/bin/stonekeep.js scan fixtures/sql-migrations
```

## `postgres-shop` (engine integration tests)

`schema.sql` + `seed.sql` + `stonekeep.connector.yaml` + a datamap generated by `stonekeep scan`. The
schema covers multi-level cascades (users → orders → order_items), a self-reference
(`users.manager_id`), a foreign key on a PII column (`login_events.user_email → users.email`), an
identity column, a soft reference declared only in YAML (`support_tickets.requester_id`) and
retained invoices. The seed values are fictional but realistic, so tests can prove none of them
leak.

```bash
pnpm build && node packages/cli/bin/stonekeep.js scan fixtures/postgres-shop
```
